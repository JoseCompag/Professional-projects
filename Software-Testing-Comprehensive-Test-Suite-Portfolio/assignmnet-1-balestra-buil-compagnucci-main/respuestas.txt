-- Ejercicio 4:
Para este ejercicio, se llevaron a cabo tests para los programas que contenian defectos (test/java/practico1_exercises/simple_routines/SimpleRoutinesTest.java), como tambien tests para los que fueron reparados (test/java/practico1_exercises/simple_routines/SimpleFixedRoutinesTest.java).

Programa 1): 
En este programa, el test que logra ejecutar el defecto y que se produzca una falla es el siguiente:
    @Test
    public void test_findLastWithFirstElement() {
        int[] array = {2, 3, 5};

        int result = SimpleRoutines.findLast(array, 2);

        assertEquals(0, result, "Array doesn't contain the searched element");
    }
Encontramos esta falla, observando las cuatro condiciones del modelo RIPR:
    - Reachability: En este caso el test ejecuta la linea que contiene el defecto, la cual es, "for (int i=x.length-1; i > 0; i--)" 
    donde la condicion de continuación del ciclo es i > 0, y este es el defecto.
    - Infection: Este defecto infecta el correcto estado del programa el cual deberia alcanzar un momento en donde la variable i sea igual a 0
    dando lugar a que el arreglo no pueda ser recorrido por completo.
    - Propagation: El estado infectado causa que el resultado del método findLast sea incorrecto, ya que no se recorre todo el arreglo.
    - Revealability: El tester puede observar el fallo en el resultado del test, ya que el método findLast no devuelve el índice correcto del elemento buscado.

Progama 2):
Test que ejecute el defecto y que produzca una falla:
    @Test
    public void test_LastZeroWithFirstElementAsZero() {
        int[] array = {0, 1, 0};

        int result = SimpleRoutines.lastZero(array);

        assertEquals(2, result, "First and last elements are a zero, expected index is not returned.");
    }
Detectamos esta falla, observando las cuatro condiciones del modelo RIPR: 
    - Reachability: El test ejecuta la línea que contiene el defecto, la cual es "if (x[i] == 0) { return i; }". 
    - Infection: Este defecto infecta el correcto estado del programa al retornar el índice del primer cero encontrado en lugar del último. 
    - Propagation: El estado infectado causa que el resultado del método lastZero sea incorrecto, ya que no se recorre todo el arreglo para 
    encontrar el último cero. 
    - Revealability: El tester puede observar el fallo en el resultado del test, ya que el método lastZero no devuelve el índice correcto del último cero.

En este programa, el test que logra ejecutar el defecto y que se produzca una falla es el siguiente:

    public void test_countPositive_withFourPositiveNumbers() {
        int[] array = {1, 2, 3, 4, 0};

        int result = SimpleRoutines.countPositive(array);

        assertEquals(4, result, "Expected the count of positive numbers to be 4, but it was not.");
    }
Para observar esta falla, se dieron 4 condiciones, como se detalla a continuación:
- Reachability: la porción de código en la que se encuentra el defecto es ejecutada, más específicamente la línea "if (x[i] >= 0)".
- Infection: una vez que la porción del código defectuosa fue ejecutada, el programa se encontró en un estado incorrecto, en donde se manifestó el defecto. 
Si se tomara una foto completa del programa, por ejemplo, en la última ejecución del ciclo for, la variable count tendría un valor incorrecto, siendo esta count = 5, 
cuando en realidad debería ser count = 4.
- Propagation: el estado infectado es propagado por el resto de la ejecución. Si bien el arreglo se recorre en su totalidad, la variable count arrastra su valor incorrecto 
hasta el final de la ejecución.
- Revealability: gracias a este test, se puede observar el resultado incorrecto de la ejecución. El método countPositive no retorna la cantidad correcta de números
positivos.
